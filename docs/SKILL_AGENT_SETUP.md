# Skill 与解剖导师

## 当前实现

管理员负责启用和授权，教师负责资料质量，学生使用已批准能力。当前提供三种预置、只读 Skill，不提供任意代码上传、远程工具安装、数据库写入或图谱编辑。

| Skill | 输入 | 输出 | 边界 |
| --- | --- | --- | --- |
| `anatomy_search` | 检索词，可选模型部件 ID | 最多 8 个结构与器官归属 | 来源为完整本地 atlas，不虚构模型 ID |
| `textbook_search` | 检索词，可选模型部件 ID | 教材片段、章节、页码和引用 | 复用教材检索；无依据时明确返回无匹配 |
| `graph_query` | 检索词，可选模型部件 ID | 一层邻域，最多 40 节点、60 边 | 只表达结构归属，不推断空间毗邻、血供或神经支配 |

AnatomyTutor 使用本地规则规划最多三个工具调用。它不是大模型自主推理，也不保证任意自然语言问题都能准确解析。未提供结构上下文时，整个问题会作为检索词；推荐传入明确的 `context`。

教材文本只作为资料展示，不能启用 Skill、修改权限或执行命令。前端展示使用 Vue 文本插值，不把教材内容当 HTML 执行。涉及个人病情的部分典型表述会返回教学边界提示，但关键词识别不是完整的医疗安全分类器。

## 管理流程

1. 管理员登录并进入 `/admin/skills`。
2. 对需要的能力勾选启用和允许角色，设置每账号小时额度，然后保存。
3. 需要用管理员账号测试时，允许角色必须包含“管理员”；测试不绕过启停或额度。
4. 学生在虚拟解剖室选择结构，点击讲解，查看教材依据和真实调用状态。
5. 在管理员页查看成功、无匹配、禁用、无权限、额度耗尽或失败的记录。

首次启动全部 Skill 关闭，不自动替管理员批准。无匹配、拒绝或故障时，Agent 不通过旧讲解分支偷偷检索作为兜底；独立教材与图谱浏览接口仍保留，Skill 开关不是这些资源的访问控制开关。

## API

管理接口只允许真实 `admin` / `super_admin` 会话访问。

```json
{
  "enabled": true,
  "allowed_roles": ["student", "teacher", "admin"],
  "hourly_limit": 120
}
```

以上为 `PUT /api/admin/skills/textbook_search` 的请求体。

```json
{
  "message": "请查询它的组成关系和教材依据",
  "active_module": "anatomy_lab",
  "context": {"query": "心脏"}
}
```

以上为 `POST /api/agent/chat` 的请求体。请求使用 `Authorization: Bearer <token>`。保留 `role` 字段仅用于兼容旧客户端，后端忽略它并从登录会话获取实际身份。返回值兼容原讲解协议，并增加 `execution_mode`、`skill_results`、`citations`、`actions`。只有成功检索产生来源与操作目标。

## 持久化与审计

配置和调用记录保存在 `data/skills.sqlite3`，路径可通过 `SKILL_DATABASE_PATH` 指定；文件及 journal/WAL 已加入 `.gitignore`。管理员配置同时进入原有管理审计日志。调用记录包含真实账号、角色、运行 ID、Skill、状态与耗时，不存原始问题、教材正文或密钥。

权限检查与额度预留使用 SQLite 事务，额度按“Skill + 账号 + 滚动一小时”计数。执行中、成功、无匹配和执行失败都会占用额度；禁用、无权限和额度拒绝不占额度。禁用影响后续调用，不会强制取消已开始的只读检索。

## 验证与限制

```powershell
conda activate pytorch_env
python -m pytest backend/tests/test_skills.py -q
pnpm --dir frontend build
```

自动测试覆盖默认关闭、权限拒绝、角色伪造、并发额度、即时禁用、配置持久化、失败脱敏、无匹配、教材来源、检索指令隔离与真实 API 会话。

当前没有接入 LLM 工具选择，不会新增 LLM 调用费用；教材语义检索可能沿用现有 Embedding 服务。上线前仍需加入请求限流、调用记录留存策略、共享生产存储、管理员配置并发版本控制及更全面的医学安全评测。新增 Skill 必须由开发者提供并测试适配器，再由管理员启用，不能只提交一个名称或提示词获得执行权限。
