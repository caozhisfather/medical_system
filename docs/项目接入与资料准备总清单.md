# 临思智训项目接入与资料准备总清单

> 用途：按此清单准备外部模型、医学资料和部署环境，再逐项验收。平台仅用于教学训练，不用于真实临床诊疗。

## 一、必须准备的 API

### 1. AI 标准化病人模型

- [ ] 提供 OpenAI 兼容的 `chat/completions` 地址，或项目专用问答接口。
- [ ] 配置 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。
- [ ] 模型输入至少包含：病例 ID、主诉、既往史、当前对话、允许披露的症状事实。
- [ ] 模型输出只返回病人表达，不主动泄露诊断、检查答案和评分标准。
- [ ] 明确超时、限流、费用上限和不可用时的本地回退策略。
- [ ] 准备 20 至 50 条人工验收对话，覆盖追问、否定、模糊回答、情绪表达和高风险症状。

### 2. Qwen/DashScope Embedding API

- [ ] 配置 `EMBEDDING_API_KEY`（也兼容 `DASHSCOPE_API_KEY`、`QWEN_API_KEY`）。
- [ ] 配置 `EMBEDDING_BASE_URL` 和 `EMBEDDING_MODEL`，默认模型为 `text-embedding-v3`。
- [ ] 确认单次输入长度、批量大小、维度、并发限制和计费规则。
- [ ] 为每个文档保存 `document_id`、页码、章节路径、文本哈希和模型版本。
- [ ] 导入或修改资料后重建索引，并抽样验证“右心房”“十二指肠”等关键词命中正文页。

### 3. OCR 服务

- [ ] 选择本地 OCR 或云 OCR，并配置对应 endpoint、密钥和语言（中文、英文、数字、表格）。
- [ ] 需要支持 PDF 扫描页、双栏排版、表格、图片标题和页码识别。
- [ ] 输出页级文本、页码、章节标题、置信度和原图坐标。
- [ ] 自动标记目录、版权页、空白页、参考文献页，避免进入解剖检索结果。
- [ ] 管理员可以预览、纠正章节、删除错误页后再生成 embedding。

### 4. 数字人病人语音/视频

- [ ] 准备病人专用头像或视频素材，不能继续使用导师素材。
- [ ] 选择 TTS、口型驱动或实时数字人服务，配置 `TTS_PROVIDER`、`LIVEACT_SERVICE_URL`、`LIVEACT_AVATAR_ID`。
- [ ] 服务接口至少支持：文本、情绪、动作、音频/视频 URL、生成状态、失败原因。
- [ ] 前端保留“文字问诊”和“数字人病人”两种模式；视频生成失败时仍显示文字回答。
- [ ] 验收字幕、音频、视频三者内容一致，并确认不会把诊断答案显示给学生。

## 二、医学资料收集

- [ ] 系统解剖学（含心脏四腔、瓣膜、消化道分段、神经和血管细节）。
- [ ] 组织学、胚胎学、生理学、生物化学、病理学、病理生理学、药理学。
- [ ] 诊断学、实验诊断学、医学影像学、临床检验解读。
- [ ] 内科、外科、妇产科、儿科、急诊、传染病、精神科、全科医学教材。
- [ ] 国家卫健委、中华医学会/中国医师协会指南、国家临床路径。
- [ ] WHO、CDC、NICE、AHA、ESC、IDSA、Cochrane、PubMed Central 等公开权威来源。
- [ ] 每份资料记录标题、作者/机构、版本、发布日期、来源链接、版权许可、适用科室和页码。
- [ ] 仅导入合法授权或公开许可内容；资料进入学生端前完成脱敏和教师审核。

## 三、知识库处理流程

1. 管理员上传原始 PDF/Word/图片并登记来源和版权。
2. OCR 按页解析，自动过滤目录、空白页和版权页。
3. 管理员在预览中修正章节、页码和错识别文本。
4. 系统执行姓名、电话、住址、身份证、住院号等脱敏并保留审计记录。
5. 调用 Embedding API 生成向量，保存模型版本和文本哈希。
6. 生成知识图谱节点/关系，标注来源页码。
7. 教师编辑教学摘要、病例脚本和评分点；管理员审核来源与发布状态。
8. 发布后支持增删改查、撤回、重建索引和失败重试。

建议状态：`待上传` → `OCR 中` → `待清洗` → `待脱敏` → `待审核` → `已发布` → `Embedding 待生成` → `已索引`。

## 四、权限与安全

- [ ] 管理员负责资料上传、删除、脱敏、来源、索引和发布权限。
- [ ] 教师负责病例教学编辑、Agent 整合、审核后发布训练任务。
- [ ] 学生只能读取已发布资料和自己的训练结果，不能看到标准答案和原始隐私字段。
- [ ] API 密钥只放在后端 `.env` 或密钥管理服务，不提交 Git，不写入前端。
- [ ] 记录上传、修改、删除、审核、发布、检索和导出审计日志。
- [ ] 对所有 AI 输出增加“教学用途”提示、引用依据和人工复核入口。

## 五、可选基础设施

- [ ] Chroma（单机演示）或 Milvus（多人/生产）向量数据库。
- [ ] Neo4j（图谱查询）或继续使用 JSON 图谱（原型阶段）。
- [ ] 对象存储保存原始文件、OCR 页面图和数字人视频。
- [ ] Redis/Celery 或队列服务处理 OCR、Embedding、图谱更新等异步任务。

## 六、最终验收

- [ ] 学生可以选择文字问诊或数字人病人，且两种模式共享同一病例事实。
- [ ] 病人不会主动泄露诊断；高风险内容触发安全提示。
- [ ] 教师可从知识库选择病例，调用 Agent 生成草稿，编辑、审核、发布或撤回。
- [ ] 管理员可上传、预览、脱敏、纠错、删除、重建 Embedding，并查看处理状态。
- [ ] 检索结果显示来源、章节、页码、版本和引用链接。
- [ ] 解剖定位点击后能进入细化结构，详情内容有教材出处。
- [ ] 报告包含问诊过程、检查理由、用药风险、六维能力画像、错因和可追溯证据。
- [ ] 前端 `pnpm build` 成功，后端在 `pytorch_env` 环境下 `python -m compileall -q backend` 成功。
- [ ] 断开所有外部 API 后，演示模式仍可启动并给出明确回退提示。
